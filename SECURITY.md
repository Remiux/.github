# Security policy

This policy applies to every repository in the
[Remiux](https://github.com/Remiux) organization that has no security policy of
its own.

## Report a vulnerability

Do not open a public issue, discussion, or pull request for a security
vulnerability.

Report it privately through GitHub:

1. Open the affected repository.
2. Go to the **Security** tab.
3. Select **Report a vulnerability**.

The report is visible only to you and the repository's maintainers.

Include as much of the following as you can:

- the affected repository, and the version, tag, or commit;
- the type of issue, for example injection, broken authentication, or exposed
  credentials;
- the steps to reproduce it, or a proof of concept;
- the impact: what an attacker could read, change, or disrupt.

## What happens next

1. We acknowledge the report within **5 business days**.
2. We confirm whether the issue is a vulnerability and assess its severity.
3. We keep you informed while we work on a fix, and tell you when the next
   update will come.
4. We publish a fix and, where it applies, a GitHub security advisory. We
   credit you in the advisory unless you ask us not to.

Please give us reasonable time to release a fix before you disclose the issue
publicly.

## Supported versions

Security fixes are made on the default branch and the latest release of each
repository. Older versions are not patched unless a repository's own policy
says so.

## Scope

In scope: code in Remiux repositories on GitHub.

Out of scope: vulnerabilities in third-party dependencies that are already
public — report those to the project that maintains them — and findings from
automated scanners submitted without a demonstrated impact.
